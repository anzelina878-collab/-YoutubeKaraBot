# Railway

1. Создайте отдельный приватный репозиторий GitHub youtube-kara-bot. Загрузите файлы из этой папки в корень репозитория, без .env и state.sqlite3.
2. Railway → New Project → Deploy from GitHub repo → выберите этот репозиторий. При необходимости предоставьте Railway доступ только к нему.
3. В сервисе откройте Variables и добавьте TELEGRAM_BOT_TOKEN, TELEGRAM_CHAT_ID, YOUTUBE_API_KEY. Значения вводятся только в Railway. Добавьте DATABASE_PATH=/data/state.sqlite3.
4. Добавьте постоянный Volume к сервису и укажите Mount Path /data. Не создавайте собственную переменную RAILWAY_VOLUME_MOUNT_PATH.
5. Оставьте одну реплику. Serverless/App Sleeping выключите, если включено: процесс должен постоянно работать. Домен, входящий порт и HTTP healthcheck этому worker не нужны. Dockerfile и railway.json задают сборку и запуск.
6. Deploy. В логах должна появиться строка «Бот запущен». Если ещё нет ключей, процесс завершится с сообщением об отсутствующих переменных — это ожидаемо.
7. Первая отправка будет в ближайшее окно расписания. Для ручной проверки в терминале сервиса: python bot.py --once. Эта команда действительно отправляет сообщения настроенному получателю и расходует квоту YouTube.

Для chat_id: сначала нажмите Start у своего бота, затем выполните локально python bot.py --setup с токеном в .env. Сопоставьте выведенный username со своим аккаунтом. Не передавайте токен сторонним ботам для получения chat_id.

Перед запуском проверьте актуальные условия оплаты в Railway. На один сервис с volume не включайте параллельные экземпляры. Сохранность истории повторных отправок зависит от сохранности volume.

Документация: https://docs.railway.com/services и https://docs.railway.com/volumes

Обновление: MAX_SUBSCRIBERS=300000 по умолчанию. Сообщения — карточки идей по четырём редакционным направлениям. Нужны два независимых канала с доступной статистикой и сравнением не менее 2× среднего темпа соседних видео. Без достаточных сигналов рассылка пропускается.
