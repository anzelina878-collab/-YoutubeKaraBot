# YouTube Niche Bot

Личный Telegram-бот, Python 3.11+. Зависимости Python не нужны.
Расписание: 10, 12, 14, 16, 18, 20 часов Europe/Kyiv, с переходом на летнее время.

## Создание и настройка

1. Откройте https://t.me/BotFather, отправьте `/newbot`, задайте имя и уникальное имя пользователя, оканчивающееся на `bot`.
2. Сохраните полученный токен только в локальном `.env`: скопируйте `.env.example` в `.env` и заполните `TELEGRAM_BOT_TOKEN`. Не публикуйте файл и не отправляйте токен в чат.
3. Откройте своего бота, нажмите Start. В каталоге проекта выполните `python bot.py --setup`. Найдите свой username в выводе и сохраните его chat_id в `TELEGRAM_CHAT_ID` файла `.env`. Это адрес получателя; бот не подписывает посторонних пользователей.
4. В Google Cloud Console создайте проект, включите YouTube Data API v3, создайте API key с ограничением на этот API. Запишите его в `YOUTUBE_API_KEY` в `.env`. Не присылайте ключ в чат.
5. Предпросмотр без Telegram: `python bot.py --dry-run` (использует настоящую квоту YouTube).
6. Первая отправка: `python bot.py --once`. Далее: `python -u bot.py`.

С Docker Compose на постоянно работающем сервере: `docker compose up -d --build`.
Для настройки chat_id можно использовать Python на локальном компьютере.
Состояние Compose сохраняется в `data/`; сохраняйте его при обновлениях.
Не запускайте несколько экземпляров с одной базой. Облачная сессия Codex не является постоянным хостингом.

## Что делает первая версия

- В каждом цикле выполняет восемь языковых запросов, до 10 результатов на запрос.
- Ищет обычные видео за последние 30 суток, на этапе поиска длиннее 20 минут, затем дополнительно проверяет длину от 8 минут. Это консервативная выборка: ролики 8–20 минут пока не попадают в поиск.
- Отправляет до 6 новых видео за цикл, минимум 10 тысяч просмотров по умолчанию.
- Показывает оригинальное название, дату, длительность, просмотры, язык поиска, язык аудио из метаданных при наличии и ссылку.
- Сравнивает средние просмотры в день с медианой доступных соседних видео канала, если их не менее трёх. Это приближение: возраст публикаций и распределение просмотров различаются.
- Не отправляет видео повторно после успешной доставки. При аварии между отправкой и сохранением возможен повтор.
- Хранит наблюдения просмотров в SQLite. Пока не рассчитывает ускорение роста.
- Не отправляет пустые подборки. После сбоя повторяет цикл не чаще чем раз в 10 минут в текущем часовом окне.

Это автоматический сборщик кандидатов, а не полный исследовательский skill: не смотрит содержание видео, не переводит заголовки, не группирует темы семантически и не подтверждает независимую повторяемость ниши. Поисковые запросы охватывают преимущественно объясняющий и документальный контент; полный охват любых ниш не заявляется. Запросы можно менять в `LANGS` внутри `bot.py`.

Ориентировочная квота: 48 search.list в день = 4800 единиц, плюс запросы метаданных и сравнений; повторы, ручные запуски и другие приложения увеличивают расход. Проверьте фактическую квоту проекта в Google Cloud. Поиск, отбор и рассылка работают без OpenAI API.

Проверка: `python -m unittest -v`. Проверены фильтр даты/длины, часы зимой и летом, запись отправки в базу. Живые API не проверены: ключи не подключены.
